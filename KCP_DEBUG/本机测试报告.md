# 本机测试报告（Loopback 全栈）

> 测试时间：2026-07-02
> 测试对象：方案A（存活探测解耦 + 指数退避判死 + 应用重传对可靠底层退让）落地后的 KCP/DualStream 传输
> 结论：**通过**。全栈 5 进程本机模拟，20MB 文件经隧道端到端传输，SHA256 三次一致，吞吐稳定 ~18 MB/s。

---

## 1. 测试拓扑（全部 127.0.0.1，单机 5 进程）

```
tunclient(:18888) ──P2P隧道(经relay)──> tunserver ──> httpfileserver(:15173, 20MB)
      │                                     │
      └──── relay(:19001) ────┘             │
                 │                          │
            index(:19000) <────注册─────────┘
```

| 进程 | 角色 | 地址 |
|---|---|---|
| nodeserver -mode index | 索引/引导 | :19000 |
| nodeserver -mode relay | 公网中继 | :19001（注册到 index） |
| httpfileserver | 源站（20MB 文件） | :15173 |
| tunserver | NAT 节点 A（隧道服务端，转发到源站） | 经 relay 注册 |
| tunclient | NAT 节点 B（隧道客户端，本地监听） | :18888 |

数据路径：`curl → tunclient:18888 → [P2P/DualStream(KCP优先) 经 relay] → tunserver → httpfileserver`。

### 3.4 关键：无误杀
三次运行全程日志中 **无** `keepLive 判死` / `心跳失败` / `leg 失败` / `unreachable` / `failAndClose`。
说明方案A 的存活探测在正常传输下**从不误触发**（连接持续有帧 → `lastRecvMicros` 持续刷新 → 永不进入判死流程），与设计预期一致。

## 4. 单元/集成测试（同机）

- `go build ./...`：通过。
- `go test ./networkFrameWork/ -count=1 -timeout 300s`：**全部通过**（143s，含 60s 的 RelayHashChain 长稳测试）。
- `go test ./networkFrameWork/ -race -run '^TestConnectionStability|^TestDualDial|^TestAdaptiveAckTimeout_Logic$|^TestWaitAck'`：**race 干净**。
- 值得注意：`TestConnectionStabilityKCPBlocked` / `KCPDisconnected` 仍在 ~1.1s 内通过 —— 证明「阻塞/断开 KCP leg → 快速 failover 到 TCP + KCP 自愈重连」不受判死放宽影响（阻塞/断连经 readLoop/Write 立即报错杀 leg，与 keepLive 探测无关）。

## 5. 落地改动摘要（本机验证覆盖的代码）

| 改动 | 文件 | 作用 |
|---|---|---|
| 新增连接级 `lastRecvMicros`（atomic），readLoop 每帧刷新 | `networkFrameWork/TcpStream.go` | 存活判活信号源（覆盖一切入站帧） |
| `keepLive` 改为「静默基线 + 指数退避 6 次探测」判死 | `networkFrameWork/TcpStream.go` | 判死与 app-ACK 时延解耦，消除抖动误杀 |
| 应用重传超时放宽（初始/下限 800ms、×4 SRTT、上限 8s、退避封顶） | `networkFrameWork/TcpStream.go` | 不与底层 RTO 抢跑，重传退化为兜底 |
| 修复 `networkCaller_test.go` 泄漏 goroutine 在测试结束后 `t.Errorf` | `networkFrameWork/networkCaller_test.go` | 判死放宽后连接保活更久，暴露的既有测试缺陷 |

## 6. 局限与说明

- 本报告为 **loopback（0 RTT、0 丢包）** 环境：验证的是**功能正确性、完整性、无误杀、吞吐基线**。
- 存活探测/双重 ARQ 的**真实价值**（跨境 KCP 丢包下不误杀、不雪崩）**loopback 无法体现** —— 由《跨relay通信测试报告》在真实链路（relay/index 在国内 129/193 服务器）覆盖。
- 吞吐 ~18 MB/s 为本机隧道 + 加密 + 组帧 + relay 转发的综合结果，非纯 KCP 上限。
